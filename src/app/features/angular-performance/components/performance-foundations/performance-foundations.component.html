01 · Fundamentos y métricas

Performance es experiencia cuantificada

“Se siente rápida en mi laptop” NO es evidencia. Una decisión técnica válida une una acción del usuario con una métrica reproducible, un diagnóstico y una mejora medida antes/después.

Loading

LCP ≤ 2.5 s

Largest Contentful Paint mide cuándo aparece probablemente el contenido principal más grande visible. Suele sufrir por hero images, CSS/fuentes bloqueantes, respuesta del servidor o demasiado JavaScript inicial.

Interaction

INP ≤ 200 ms

Interaction to Next Paint refleja capacidad de respuesta durante las interacciones. Long tasks, cálculos síncronos, renders amplios y listeners costosos bloquean el siguiente frame que la persona espera ver.

Visual stability

CLS ≤ 0.1

Cumulative Layout Shift registra desplazamientos inesperados. Imágenes sin dimensiones, placeholders con tamaño incorrecto, fuentes o contenido tardío deterioran la confianza y pueden provocar clics equivocados.

Campo frente a laboratorio

Field / RUM / CrUX
Expone dispositivos, redes, datos y recorridos reales. Core Web Vitals se evalúa en el percentil 75, segmentando móvil y desktop.
Lab / DevTools / Lighthouse
Permite reproducir, perfilar y comparar cambios controlados. Sirve para diagnosticar, no para sustituir la realidad del usuario.

Métricas diagnósticas adicionales

  • TTFB: señala latencia de servidor, CDN, SSR o caché antes del contenido.
  • FCP: marca el primer contenido pintado; no asegura que el contenido principal esté listo.
  • TBT / long tasks: ayudan en laboratorio a investigar bloqueo del main thread relacionado con mala interacción.
  • Bundle y waterfall: revelan bytes, prioridades, dependencias o terceros costosos.
Nota Expert: define budgets por journey, no solo por página: carga del landing, apertura de búsqueda, escritura en formulario y navegación autenticada pueden tener causas y métricas diferentes. Un promedio puede ocultar que tus usuarios lentos están abandonando.
