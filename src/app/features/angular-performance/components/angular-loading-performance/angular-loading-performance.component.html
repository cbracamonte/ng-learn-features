02 · Carga y entrega

Enviar lo necesario, en el momento correcto

Reducir el JavaScript inicial solo tiene valor si el contenido prioritario llega antes y el usuario no paga luego una espera sorpresiva. La estrategia se decide por criticidad visual y de interacción.

Herramientas Angular de carga y sus tradeoffs
Problema Palanca Angular / web Cuidado Senior
Features no usadas en entrada loadComponent o rutas lazy No precargues todo otra vez sin evidencia de navegación probable.
Widgets secundarios pesados @defer con trigger y estados No difieras contenido LCP visible si introduces CLS o espera crítica.
Imagen hero o galería pesada NgOptimizedImage, priority, dimensiones priority es para candidatos LCP, no para toda la galería.
SSR que vuelve a recrear DOM Hydration; incremental hydration cuando aplica Requiere SSR/hidratación correctamente configurados y HTML consistente.

@defer: diferir con intención

  • Angular divide dependencias standalone del bloque en carga dinámica.
  • Triggers útiles: idle, viewport, interaction, hover, timer o condición when.
  • Modela UX con @placeholder, @loading y @error; reserva espacio para proteger CLS.
  • prefetch puede bajar latencia futura, a cambio de consumir red antes de uso real.

Imágenes, LCP y estabilidad

  • NgOptimizedImage lazy-loads imágenes no prioritarias y puede generar srcset.
  • Marca la imagen candidata a LCP con priority; Angular aplica prioridad alta y advierte en desarrollo si falta.
  • Declara width/height para reservar relación de aspecto y prevenir layout shifts.
  • CDN, tamaños responsivos, compresión y preconnect importan tanto como la directiva.

SSR e hidratación

Con SSR, hidratación reutiliza el DOM generado en servidor en lugar de destruirlo y renderizarlo otra vez en cliente. Angular documenta beneficios medibles sobre LCP y CLS. La hidratación incremental puede conservar zonas diferidas sin hidratarlas hasta requerirse.

Fuera del framework

  • Reduce fuentes, CSS crítico bloqueante y scripts de analytics/chat sin prioridad.
  • Evita waterfalls API secuenciales si los datos pueden solicitarse en paralelo.
  • Define políticas HTTP/CDN de caché e invalídalas con versionado correcto.
