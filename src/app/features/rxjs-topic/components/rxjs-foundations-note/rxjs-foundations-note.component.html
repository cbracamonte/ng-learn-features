RxJS: contratos de valores distribuidos en el tiempo

Base Senior

Un Observable representa una secuencia potencial de valores a lo largo del tiempo. La clave arquitectónica no es “usar operadores”: es definir un contrato sobre cuándo empieza el trabajo, cuántos valores puede entregar, cómo termina y quién lo cancela.

Source

Origen

HTTP, input, websocket, timer o evento de dominio.

Pipeline

pipe()

Transforma, filtra, combina y decide concurrencia.

Subscription

Ejecución

Activa el consumo; puede iniciar trabajo en fuentes cold.

Teardown

Liberación

Complete, error o unsubscribe finalizan recursos.

Modelo mental de entrevista

  1. 1. Identifico la fuente y si es única o continua.
  2. 2. Defino si debo cancelar, encolar, paralelizar o ignorar.
  3. 3. Modelo estados de UI: loading, data, empty y error.
  4. 4. Decido lifetime, sharing y política de cache.

Cold Observable

Cada suscripción inicia su propia ejecución. Una request HTTP o un defer() puede repetirse si múltiples consumidores se suscriben.

Pregunta clave: ¿duplicar el trabajo es correcto o debo compartirlo?

Hot / multicasted stream

Los consumidores observan una ejecución compartida, como un Subject o una fuente transformada con sharing. Compartir exige decidir replay, invalidación y lifetime.

Compartir sin política produce memoria retenida o datos obsoletos.

Regla Senior · El operador se elige DESPUÉS de la semántica

Antes de decir switchMap o mergeMap, explica qué comportamiento exige el negocio ante eventos concurrentes. El operador es la implementación de esa política, no una preferencia estética.
