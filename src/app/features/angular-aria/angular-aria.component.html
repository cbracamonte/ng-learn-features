Angular Aria

Headless accessibility patterns

Angular Aria no te regala componentes visuales listos. Te da directivas headless para patrones WAI-ARIA: teclado, roles, estados ARIA, foco y soporte para screen readers. Vos ponés estructura, estilos y criterio.

Qué problema resuelve

Un accordion o tabs parece fácil hasta que aparecen flechas, Home/End, aria-controls, aria-expanded, roving tabindex y contenido inerte. Ahí se separa el copy-paste del laburo profesional.

Cuándo usarlo

  • Design systems con visual propio.
  • Component libraries enterprise.
  • Interfaces custom donde Angular Material queda corto visualmente.

Cuándo NO usarlo

  • Si necesitás componentes pre-estilizados rápido: usá Angular Material.
  • Si un control nativo alcanza, no inventes un widget ARIA.
  • Si no vas a testear teclado y screen reader, frená y ponete las pilas.
