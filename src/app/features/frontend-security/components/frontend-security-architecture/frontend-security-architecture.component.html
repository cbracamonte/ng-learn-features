Parte 3 · Navegador, API e infraestructura

Controles que Angular no puede resolver por sí solo

Autenticación, sesiones y tokens

  • Evita guardar identificadores de sesión o tokens sensibles en localStorage: cualquier XSS puede leerlos.
  • Para sesiones web, evalúa cookies HttpOnly, Secure y SameSite, o patrón BFF.
  • Si usas cookies autenticadas, diseña CSRF correctamente; HttpOnly no previene CSRF.
  • No incluyas client secrets, claves privadas ni credenciales privilegiadas en variables del bundle Angular.

API, CORS y autorización

  • CORS controla qué orígenes pueden leer respuestas en navegadores; NO autoriza usuarios.
  • Valida en servidor payload, identificadores, permisos, roles, tenant y ownership.
  • No confíes en validación de formulario, campos ocultos, precio calculado o claims editables del cliente.
  • Diseña respuestas para no revelar PII, stack traces o permisos innecesarios.

Headers y políticas del navegador

Control Reduce Nota Senior
CSP estricta Ejecución de scripts/recursos no permitidos y clickjacking con frame-ancestors. Defensa en profundidad; no sustituye corregir sinks XSS.
Trusted Types Asignaciones string inseguras hacia sinks DOM sensibles. Angular tiene políticas requeridas al habilitar enforcement.
HSTS Downgrade HTTP tras una visita segura. Lo entrega el servidor/CDN, no el código Angular.
Referrer-Policy Filtración de URLs/datos a destinos externos. No pongas secretos ni PII en query params de todas formas.
Permissions-Policy Uso no requerido de cámara, micrófono, ubicación u otras capabilities. Limita capacidades aunque una integración intente utilizarlas.

Navegación, archivos y contenido externo

  • Valida redirects y URLs externas contra allowlists; evita open redirect y esquemas peligrosos.
  • En enlaces con nueva pestaña, usa protección contra acceso a window.opener.
  • Uploads: valida tamaño/tipo en cliente por UX, pero inspecciona y almacena seguro en servidor.
  • Downloads/previews: no renderices HTML o SVG no confiable con privilegios del origen.
  • Iframes externos requieren allowlist, sandbox mínimo necesario y política de framing.

Supply chain y código tercero

  • Actualiza Angular y dependencias; revisa advisories, lockfile y origen de paquetes.
  • Un tag de analytics o chat ejecuta JavaScript con acceso a tu página: trátalo como dependencia privilegiada.
  • Usa CSP y, cuando aplique para recursos CDN estáticos, Subresource Integrity.
  • No publiques source maps o configuración sensible sin una decisión operacional explícita.
  • Reduce terceros: cada script adicional amplía tu superficie y riesgo de cadena de suministro.

SSR, hidratación, logs y datos sensibles

  • Todo estado serializado en HTML para hidratación es visible al navegador; no transfieras secretos.
  • No registres tokens, passwords, documentos o respuestas con PII en consola, analytics o telemetry.
  • Considera caché compartida/CDN al renderizar contenido autenticado: evita mezclar respuestas entre usuarios.
  • Los mensajes de error de la UI deben orientar sin revelar detalles internos del sistema.

Regla Senior · No conviertas un control cliente en una promesa de seguridad

La validación frontend mejora UX; CORS limita lectura cross-origin; un guard limita navegación; CSP contiene explotación. Ninguno sustituye autenticación, autorización y validación en servidor. Explicar esa separación es esencial en una entrevista.
