Checklist de entrevista y revisión de seguridad

Respuesta corta que debes dominar

“Angular reduce XSS en templates mediante escape/sanitización contextual y aporta el cliente XSRF en HttpClient. Yo evito bypasses y DOM directo, habilito CSP y Trusted Types, diseño sesiones seguras y exijo autorización/validación servidor-side. Guards, CORS y validaciones de UI no son barreras de autorización.”

Matriz: amenaza frente a responsable de la mitigación
Caso Angular ayuda con Aún debes implementar
XSS en template Escape/sanitización de bindings. Evitar bypass/DOM directo; CSP + Trusted Types; auditar terceros.
CSRF con cookie Header XSRF para mutaciones same-origin. Backend genera y valida token; cookies seguras; SameSite apropiado.
Acceso a ruta admin Guard para UX/navegación. API autoriza cada acción y objeto solicitado.
Robo de token No es una protección de framework. Minimizar storage accesible a JS; cookie/BFF, XSS defense, rotación y revocación.
Clickjacking No lo resuelve el component model. CSP frame-ancestors o header compatible desde infraestructura.
Dependencia comprometida Mantener framework actualizado reduce defects conocidos. Gobernanza de dependencias/terceros, CSP, SRI aplicable y monitoreo.

Revisión de código

  • Buscar bypassSecurityTrust*, DOM directo y sinks HTML/URL.
  • Revisar redirects, iframes y enlaces externos.
  • Auditar storage, logs y exposición de PII/tokens.
  • Confirmar que guards no sustituyen autorización de API.

Pruebas

  • Probar payloads XSS en campos que se renderizan o producen URLs.
  • Probar CSRF/headers y autorización con IDs/roles manipulados.
  • Verificar CSP/Trusted Types en deployment real.
  • Ejecutar análisis de dependencias y pruebas dinámicas autorizadas.

Operación

  • Actualizar dependencias frente a vulnerabilidades reportadas.
  • Monitorear CSP reports, autenticación y anomalías de API.
  • Rotar credenciales y revocar sesiones ante incidentes.
  • Mantener proceso de disclosure y respuesta a vulnerabilidades.
