Qué seguridad provee Angular — y dónde termina

Protección principal: XSS en bindings de template

Angular trata los valores enlazados como no confiables por defecto. En interpolaciones y bindings aplica escape o sanitización según el contexto del DOM. La práctica preferida es renderizar mediante templates Angular y evitar construir DOM o templates con strings externos.

Contextos de seguridad de Angular
Contexto Ejemplo Criterio seguro
HTML [innerHTML] Angular elimina contenido peligroso; prefiere texto/interpolación si no requiere HTML.
Style [style.background] No conviertas estilos externos en una vía para URLs o comportamiento inesperado.
URL [href], [src] Angular sanitiza URLs inseguras; valida destinos permitidos por negocio.
Resource URL iframe src, scripts cargables No puede sanitizar código ejecutable arbitrario; requiere allowlist y revisión estricta.

bypassSecurityTrust*: zona roja

  • No “sanitiza”; marca un valor como confiable y evita la protección normal.
  • Debe estar lo más cerca posible del origen, tras validar/armar un valor conocido.
  • Nunca lo uses sobre HTML, URLs o contenido suministrado por usuario o API sin auditoría.
  • Todo uso debe aparecer como finding obligatorio en code review de seguridad.

DOM directo y terceros

  • ElementRef.nativeElement, document y plugins DOM pueden omitir sanitización Angular.
  • No introduzcas datos no confiables en innerHTML o sinks equivalentes manualmente.
  • Si una integración lo exige, aplica sanitización contextual y revisa CSP/Trusted Types.
  • Nunca construyas templates Angular concatenando contenido de usuarios.

XSRF con HttpClient

Para requests mutantes same-origin/relativas, Angular puede leer la cookie XSRF-TOKEN y enviar X-XSRF-TOKEN. Puedes personalizar nombres con withXsrfConfiguration().

Límite: el backend debe emitir el token y validarlo. Angular solo implementa la mitad cliente del protocolo.

Router guards

Guards mejoran navegación: evitan mostrar pantallas inútiles y redirigen usuarios según estado conocido. Angular documenta explícitamente que nunca son la única fuente de access control.

Regla: cada endpoint debe validar autenticación, rol y ownership del recurso.

Hardening recomendado por Angular

Mantén Angular actualizado, usa compilación AOT en producción y refuerza los sinks del DOM mediante una política CSP estricta y enforcement de Trusted Types. Estas capas cubren caminos que pueden escapar a los bindings habituales.
