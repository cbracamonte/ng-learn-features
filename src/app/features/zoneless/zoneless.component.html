Observa quién notifica el render

Las tres tarjetas ejecutan cambios reales. No te limites a mirar el resultado: identifica el contrato. La señal notifica automáticamente; la propiedad legacy silenciosa rompe el contrato; markForCheck() lo repara de manera explícita.

Pregunta de estudio

Si sustituyeras el setTimeout por el callback de una librería de mapas, sockets o pagos, ¿dónde convertirías el dato a un signal o llamarías a markForCheck()? ESA frontera es la decisión arquitectónica importante.

Resumen para repasar

  1. 1. Zone.js observaba tareas asíncronas parcheando APIs; no conocía el estado de negocio.
  2. 2. Zoneless conserva detección de cambios, pero requiere notificaciones Angular precisas.
  3. 3. Signals son el camino principal para estado de UI; markForCheck() integra legacy.
  4. 4. Los tests deben probar render notificado, no forzarlo para ocultar errores.
