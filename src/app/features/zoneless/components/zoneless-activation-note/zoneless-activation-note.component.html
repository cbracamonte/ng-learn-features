Activación y migración consciente

Versión de este laboratorio: Angular 21

Desde Angular v21, zoneless es el comportamiento predeterminado. Este proyecto conserva provideZonelessChangeDetection() en app.config.ts para que la intención didáctica sea explícita; en v21 no es necesario para habilitarlo.

Checklist de activación por versión

Contexto Acción Motivo
Angular v21+ Verificar que no se configure provideZoneChangeDetection(). Zoneless ya viene por defecto.
Angular v20 Agregar provideZonelessChangeDetection(). Activa la calendarización sin Zone.js.
Build y tests Retirar zone.js y zone.js/testing de polyfills/dependencias. Evita costo y falsas garantías de compatibilidad.

Qué SÍ notifica a Angular

  • Actualizar un signal leído desde un template.
  • Un listener enlazado en template/host, por ejemplo (click).
  • AsyncPipe, que internamente marca la vista cuando recibe valores.
  • ChangeDetectorRef.markForCheck() para integrar código imperativo.
  • ComponentRef.setInput() al establecer entradas dinámicas.

Qué NO basta por sí solo

  • Asignar una propiedad común dentro de un setTimeout.
  • Recibir un callback de SDK y mutar el modelo silenciosamente.
  • Actualizar estado de forms reactivos y asumir que la vista será calendarizada.
  • Esperar emisiones de NgZone.onStable o onMicrotaskEmpty.

Ruta de migración segura

  1. Localiza estado de UI mutado en timers, suscripciones, callbacks y SDKs.
  2. Modela estado nuevo con signal y derivados con computed.
  3. Cuando no puedas migrar todavía, llama markForCheck() después de la mutación.
  4. Adopta componentes compatibles con OnPush para revelar dependencias implícitas.
  5. Verifica integraciones externas, forms, SSR y tests antes de retirar Zone.js.

Fronteras avanzadas que se auditan en proyectos reales

SSR / estabilidad
Registra trabajo asíncrono que debe esperar la serialización mediante PendingTasks o pendingUntilEvent().
Reactive forms
setValue() y patchValue() actualizan el modelo, pero no calendarizan por sí mismos el render: conecta observables a signals o marca la vista.
Hooks de NgZone
No bases lógica en onStable, onUnstable u onMicrotaskEmpty; en zoneless no notifican el ciclo que esperabas. Para render usa afterNextRender() / afterEveryRender().
run() / runOutsideAngular()
No los elimines mecánicamente en librerías: siguen siendo compatibles y retirarlos puede perjudicar aplicaciones consumidoras que todavía usan Zone.js.

Regla senior · Migrar no es buscar y reemplazar

Cambiar la configuración es lo fácil. La arquitectura correcta es hacer explícitas las fronteras donde el estado de UI cambia. Si no puedes identificar quién notifica el render, todavía no entiendes la compatibilidad zoneless de ese flujo.
