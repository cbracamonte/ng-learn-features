Parte 1 · Fundamentos

Qué problema resuelve la detección de cambios

Empieza aquí

Una interfaz es una proyección del estado: si counter cambia, el DOM que lo muestra debe renderizarse otra vez. El problema central NO es que JavaScript pueda cambiar una variable; el problema es cómo sabe Angular qué vista necesita sincronizar y cuándo hacerlo.

Estado

Dato en memoria

seconds = 2, un resultado HTTP o el valor de un formulario.

Notificación

Señal de trabajo

Angular recibe evidencia de que una vista podría necesitar actualizarse.

Render

DOM consistente

Angular verifica las vistas necesarias y refleja el nuevo estado.

Modelo mental mínimo

  1. 1. Ocurre un evento o una tarea asíncrona.
  2. 2. El código cambia estado que afecta una vista.
  3. 3. Angular necesita una notificación válida para renderizar.

Antes: detección impulsada por Zone.js

Zone.js observaba gran parte de la actividad asíncrona del navegador. Al finalizar tareas, Angular podía ejecutar sincronización aunque no supiera si el estado realmente había cambiado.

Conveniente para código implícito; más trabajo potencial y más magia.

Ahora: detección zoneless

Angular no depende de Zone.js para calendarizar la detección. Actualiza vistas al recibir notificaciones de APIs Angular que expresan intención de render.

Menos inferencia global; el estado debe comunicar sus cambios correctamente.

Nota senior · No confundas conceptos

Zoneless no elimina la detección de cambios; elimina a Zone.js como mecanismo general para dispararla. Tampoco significa “solo signals”: AsyncPipe, listeners de template, ComponentRef.setInput() y ChangeDetectorRef.markForCheck() también notifican a Angular.
