Zone.js y monkey patching, sin misterio

¿Qué es monkey patching?

Es reemplazar o envolver una API existente en tiempo de ejecución sin cambiar el código que la consume. Quien llama a setTimeout() cree usar la función nativa, pero una capa intermedia puede registrar la tarea antes de delegar al navegador. 

// Modelo conceptual, NO implementación literal de Zone.js
const nativeSetTimeout = window.setTimeout;

window.setTimeout = (callback, delay) => {
  registerTask('timer');
  return nativeSetTimeout(() => {
    try {
      callback();              // el estado de la app puede cambiar aquí
    } finally {
      notifyTaskCompleted();   // Angular podía enterarse del fin de la tarea
    }
  }, delay);
};

APIs típicamente interceptadas

  • setTimeout / setInterval como macro-tareas.
  • Registro y ejecución de eventos mediante addEventListener.
  • Continuaciones asíncronas asociadas a promesas.

Costo arquitectónico

  • Puede disparar sincronización sin que haya cambiado estado visible.
  • Agrega capa de depuración, tamaño y costo de inicialización.
  • Nuevas APIs o librerías pueden no encajar bien con APIs parcheadas.

Regla expert · No digas “Zone.js detecta cambios”

Zone.js detecta actividad asíncrona parcheable, no el significado de tu estado. Angular usa esa señal para intentar sincronizar vistas. Esa diferencia explica por qué zoneless puede ser más preciso: las notificaciones vienen del modelo de UI, no de “algo async terminó”.
