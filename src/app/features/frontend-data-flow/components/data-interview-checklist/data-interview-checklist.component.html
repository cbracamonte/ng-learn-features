04 · Checklist Senior

Cómo defender una arquitectura de datos en entrevista

La diferencia entre Junior y Senior se ve cuando aparecen fallos: timeouts, sesión expirada, respuestas fuera de orden, caché obsoleta, SSR, métricas y tests.

Respuesta modelo

“Separo DTO, dominio y ViewModel; centralizo políticas transversales en interceptors funcionales; modelo loading/error/empty de forma explícita; uso RxJS para concurrencia y cancelación, signals/resources para estado visible cuando aplica; defino caché e invalidación; pruebo services e interceptors con utilidades HTTP de Angular y observo errores en producción.”

Checklist de decisiones para data fetching frontend
Decisión Pregunta Senior Angular ayuda con
Contrato ¿El tipo TS representa realmente la respuesta runtime? HttpClient tipado + mappers/parse
Políticas globales ¿Dónde vive auth, retry, timeout, telemetry y correlation id? Interceptors funcionales + DI
Concurrencia ¿Cancelar, encolar, paralelizar o ignorar? RxJS operators y request lifecycle
Estado UI ¿Cómo se representan loading, error, empty y stale? Signals, resources, stores/facades
SSR ¿Evitas doble fetch sin filtrar datos privados? Transfer cache y configuración HTTP

Antipatrones

  • Suscribirse en componentes sin lifetime ni manejo de error.
  • Copiar headers de auth en cada service en vez de usar interceptor.
  • Confiar en el genérico de HttpClient como si validara JSON.
  • Cachear datos dependientes de permisos sin invalidación.
  • Ocultar 401/403/409 como “ocurrió un error”.
