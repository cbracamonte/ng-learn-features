Notas senior (versión didáctica)

✅ Regla base de ownership

Elegí un owner de estado (signal o stream RxJS). Convertí en los bordes, no hagas ping-pong constante.

🧠 Mapa mental rápido

  • signal guarda estado.
  • computed deriva estado.
  • effect ejecuta side effects.
  • linkedSignal sincroniza estado editable.
  • resource resuelve estado async.

✅ Cuándo usar cada API

  • signal(): estado local mutable y explícito.
  • computed(): dato derivado, sin duplicar estado.
  • effect(): integración imperativa (logs, storage, analytics).
  • linkedSignal(): selección editable que se resincroniza con fuente reactiva.
  • toObservable(): cuando necesitás operadores RxJS (debounce/switchMap/retry).
  • toSignal(): consumir Observable como lectura simple en template/computed/effect.

⚠️ Errores comunes

  • Guardar en signal un valor que podrías derivar con computed.
  • Usar effect para “propagar estado” entre signals (acopla y complica debug).
  • Hacer conversiones signal ↔ observable varias veces sin necesidad.
  • Usar requireSync: true con fuentes async.

🛠️ Detalles finos senior

  • untracked(): leé snapshots sin crear dependencia reactiva.
  • onCleanup en effect(): liberá timers/listeners/sockets para evitar leaks.
  • equal: personalizá igualdad para frenar recomputaciones inútiles.
  • initialValue en toSignal: define estado inicial claro de UI.
